# 企业微信只读接口接入

## 模块与边界

`ruoyi-common/ruoyi-common-wecom` 使用 `com.github.binarywang:weixin-java-cp:4.8.0` 核心 SDK，自行适配 Java 21、Spring Boot 4.1.1 自动装配，不依赖 SDK 的 Spring Boot 2 starter。

模块已注册到 common 聚合、common BOM 和 `ruoyi-admin`。默认关闭，没有 HTTP 控制器；不改变三生 SSO、本地登录、HRM 来源配置或数据库。不自动绑定成员、创建用户、同步组织或分配角色。

## 配置

企业微信参数直接在 `ruoyi-admin/src/main/resources/application.yml` 的 `wecom` 段填写，不使用环境变量占位符。实际密钥建议写入同目录已被 Git 忽略的 `application-local.yml`，启动主应用时通过 `--spring.profiles.include=local` 加载该文件；不要提交含真实密钥的文件。

```yaml
wecom:
  enabled: true
  corp-id: '填写企业 ID'
  corp-secret: '填写应用 Secret'
  oauth-agent-id: 1000412
  oauth-redirect-uri: 'https://你的域名/wecom/callback'
```

| 配置项 | 说明 |
| --- | --- |
| `wecom.enabled` | 默认 `false`，启用时必须提供企业 ID 和应用密钥 |
| `wecom.corp-id` | 企业 ID |
| `wecom.corp-secret` | 自建应用 Secret，只供服务端使用 |
| `wecom.oauth-agent-id` | 自建应用 AgentId，构造授权链接时必须为正数 |
| `wecom.oauth-redirect-uri` | 完整网页授权回调地址；只查询通讯录时可留空 |

仅配置 CorpId/Secret/AgentId 不代表企业微信后台的可信 IP、可见范围、可信域名和接口权限均已配置；实际权限以企业微信响应为准。

业务模块按需声明 `ruoyi-common-wecom` 依赖并通过构造器注入 `WecomClient`；公共配置同时提供 `WxCpService` Bean。默认单应用，可自行提供同类型 Bean 替换默认 SDK 或客户端。

```java
// 在业务服务中注入 WecomClient 后调用；不要把成员对象整体写入日志。
WxCpUser member = wecomClient.getUser(userId);
```

## 接口映射

| 接口 | WecomClient 方法 | SDK 实现 |
| --- | --- | --- |
| `GET /cgi-bin/gettoken` | `getAccessToken()` | `WxCpService.getAccessToken()` |
| `GET /cgi-bin/auth/getuserinfo` | `getAuthUserInfo(code)` | `getOauth2Service().getAuthUserInfo(code)` |
| `GET /cgi-bin/user/get` | `getUser(userId)` | `getUserService().getById(userId)` |
| `GET /cgi-bin/user/list` | `listUsers(departmentId, fetchChild)` | `getUserService().listByDepartment(...)` |
| `GET /cgi-bin/department/simplelist` | `listDepartmentIds(departmentId)` | `getDepartmentService().simpleList(...)` |
| `GET /cgi-bin/department/get` | `getDepartment(departmentId)` | `getDepartmentService().get(...)` |
| `https://open.weixin.qq.com/connect/oauth2/authorize` | `buildAuthorizationUrl(state)` | 读取配置回调地址，SDK 构造 `snsapi_base` 链接并补充 AgentId |

成员 ID、授权 code 在传入 SDK 前做 URL 组件编码，防止 SDK 直接拼接造成参数注入或加号失真。SDK 的 `getUserInfo` 是另一条旧路径，本模块使用的是 `getAuthUserInfo`。

`listDepartmentIds(null)` 查询应用可见范围内的部门 ID；传正数时查询指定部门下的 ID 列表。成员查询是否递归由调用方显式决定。返回对象是 SDK 类型，可能因应用权限缺少部分字段。

## 授权和令牌

回调地址在 `wecom.oauth-redirect-uri` 配置，调用 `wecomClient.buildAuthorizationUrl(state)` 即可使用；原 `buildAuthorizationUrl(redirectUri, state)` 方法保留，供需要显式指定回调的调用方使用。企业微信管理后台还需在对应自建应用的网页授权设置中配置该地址对应的可信域名。

授权入口仅构造链接，不自动跳转或建立登录会话，当前也没有 `/wecom/callback` 回调处理接口，上述路径只是配置示例。后续需实现接收 `code`、校验 `state` 的真实业务入口，并将其完整 URL 填入配置。回调必须为已配置可信域名的 HTTP(S) 地址，不带用户信息和 URI 片段。`state` 要求 1 至 128 位字母或数字，调用方应使用安全随机值，并在服务端保存、绑定当前会话及一次性校验。收到真实 code 后调用 `getAuthUserInfo`；code 不能重放，返回 OpenId 而非 UserId 时不能直接视为内部成员登录。

默认 `WxCpDefaultConfigImpl` 在当前 JVM 缓存访问凭证并使用锁协调刷新，正常读取复用令牌；SDK 遇到过期令牌会刷新后重试。不要另写定时任务频繁强制刷新。当前未扩展 Redis 存储，多实例或其他系统共用同一应用密钥时，需要先设计统一的令牌缓存与刷新策略。

底层使用 SDK 默认 Apache HttpClient 连接池和超时（连接约 5 秒、读超时约 5 秒、连接池获取约 3 秒），连接池由 SDK 的全局构建器管理。当前未自定义多应用 HTTP 连接生命周期。

## 日志与错误

SDK 的原始 WARN 日志也可能包含带令牌的 URL。主应用已把 `me.chanjar.weixin` 与 `org.apache.http` 日志设为 `OFF`；测试使用模块自己的 `logback-test.xml` 同样关闭。其他应用复用本模块时需同步配置，不能直接开启原始请求日志。

`WecomClientException` 仅保留操作名、企业微信错误码和安全的异常类型；有意不透传 SDK 原始异常链、响应和请求 URL。用 `getErrorCode()` 区分上游业务错误，网络或 SDK 运行失败时为 null，可用 `getFailureType()` 辅助定位。返回对象和令牌不应整体记录或直接公开为无鉴权接口。

Bouncy Castle 的 `bcprov`、`bcpkix`、`bcutil` 在父 POM 中统一为项目既有 `${bouncycastle.version}`；日志版本遵循 Spring Boot 的依赖管理，不引入第二套 Commons Logging 桥接或 SDK 的 Redis 适配。

## 验证与真实联调

以下命令在 `backend/` 执行，先用 Wrapper 确认 JDK 21：

```powershell
.\mvnw.cmd -version
.\mvnw.cmd -pl ruoyi-common/ruoyi-common-wecom -am test
.\mvnw.cmd -pl ruoyi-admin -am test
```

普通测试不访问企业微信。`WecomClientTest` 使用真实 SDK 访问本地 HTTP 服务，覆盖全部远端 API 路径、JSON 解析、参数编码、令牌缓存/过期刷新、错误脱敏、授权 URL 与无效入参。配置测试使用 Spring Boot 4 的 `ApplicationContextRunner` 验证启用、关闭、缺失凭据等情况。

真实探测先将 `ruoyi-common/ruoyi-common-wecom/src/test/resources/wecom-live.example.yml` 复制为 `ruoyi-admin/src/main/resources/application-local.yml` 并填写应用配置，再显式执行。测试直接读取该文件，不要求激活 Spring profile：

```powershell
.\mvnw.cmd -pl ruoyi-common/ruoyi-common-wecom -am test '-Dwecom.live=true' '-Dtest=WecomLiveTest' '-Dsurefire.failIfNoSpecifiedTests=false'
```

可通过 `'-Dwecom.live.config=D:/配置目录/application-local.yml'` 指定其他 YAML 文件。所有应用参数和可选联调参数都从所选文件读取，不读取 `WECOM_*` 环境变量。文件应包含启用的 `wecom` 段；附加 `wecom-probe` 段仅由测试使用：

```yaml
wecom-probe:
  department-id: ''
  user-id: ''
  oauth-code: ''
  proxy-host: ''
  proxy-port: 8080
```

| 配置项 | 用途 |
| --- | --- |
| `wecom-probe.department-id` | 指定一个部门；未设置时从可见部门列表选一个，否则使用根部门 ID 1 |
| `wecom-probe.user-id` | 指定成员；未设置时选取该部门列表中的首个有效成员 |
| `wecom-probe.oauth-code` | 用户真实授权后的新 code；未设置时不执行身份查询，用后应清除 |
| `wecom.oauth-redirect-uri` | 已配置的真实回调地址；未设置时不执行真实配置的授权链接构造 |
| `wecom-probe.proxy-host` / `wecom-probe.proxy-port` | 显式指定本机已配置的 HTTP 出站代理；不会关闭 TLS 校验 |

真实探测输出 `WECOM_PROBE` 行，只记录状态、错误码、异常类型及记录数量。通讯录仅查询一个部门且不递归，读取一个成员，不输出个人资料。

- `OK`：此次真实请求成功并已解析响应。
- `REMOTE_ERROR`：实际调用失败，须查看错误码或异常类型。
- `BLOCKED`：获取凭证失败，依赖它的请求未执行。
- `NOT_RUN`：缺少所需参数，尚未验证。
- `BUILT_ONLY`：仅构造授权链接，没有进行企业微信浏览器授权。

**探测测试通过只代表探测流程正常结束，不代表所有远端接口可用，必须逐行查看结果。**
