# 组织信息来源接入说明

本项目可从外部组织信息来源只读拉取分部、部门和员工，同步到本地 `sys_dept`、`sys_user`。当前内置的来源是泛微 OA 人力资源（HRM）WebService；同步规则与来源无关，只写一份，以后接入其他来源时只需新增一个适配实现。

同步只由管理员在页面上手动触发：部门管理「同步子部门」、用户管理「同步员工」。没有定时同步、批量同步或增量同步，不同步岗位和角色，不向来源写数据，也不会因来源未返回而自动删除或停用本地数据。

## 1. 架构

```
ruoyi-admin
 └─ ruoyi-system ──依赖──► ruoyi-common-hrm（HrmClient、/hrm/* 联调接口）
       ├─ 同步规则（通用）：DeptBindingValidator、SysDeptSyncServiceImpl、UserSyncServiceImpl 等
       ├─ OrgSyncSource 接口 + 中性模型（domain/sync）
       └─ HrmOrgSyncSource（HRM 适配实现，调用 HrmClient）
```

| 位置 | 职责 |
| --- | --- |
| `ruoyi-common/ruoyi-common-hrm`（包 `org.dromara.common.hrm`） | HRM SOAP 只读客户端 `HrmClient`、查询服务和 `/hrm/*` 联调接口；不访问数据库，不依赖 system。详见模块 [README](../ruoyi-common/ruoyi-common-hrm/README.md) |
| `ruoyi-system` 的 `config/OrgSyncProperties` | 读取并校验 `org-sync.source` |
| `service/OrgSyncSource` | 组织信息来源接口，同步与绑定逻辑只依赖它 |
| `service/impl/OrgSyncSourceProvider` | 取当前启用的来源；`require()` 在未启用时抛「未启用组织信息来源，无法同步」，`find()` 供部门表单选填校验使用 |
| `service/impl/HrmOrgSyncSource` | HRM 适配：字段名、状态取值、性别、时间格式、null 结果等 HRM 细节都在这里转换为中性模型 |
| `service/impl/OrgSnapshotValidator` | 与来源无关的快照校验：ID 格式、重复 ID、缺少父级、环、跨分部记录，并按父先子后排序 |
| `service/impl/DeptBindingValidator` | 部门新增、修改时的绑定校验 |
| `service/impl/SysDeptSyncServiceImpl`、`DeptSyncPlanner`、`DeptSyncWriter`、`DeptSyncLock` | 部门子树同步 |
| `service/impl/UserSyncServiceImpl`、`UserSyncPlanner`、`UserSyncWriter` | 部门员工同步 |
| `domain/sync/` | 中性模型 `OrgSubcompany`、`OrgDepartment`、`OrgDepartmentSnapshot`、`OrgEmployee` 及同步计划、本地状态 |

前端：部门页逻辑在 `plus-ui/src/views/system/dept/useDeptSync.ts`，用户页在 `plus-ui/src/views/system/user/useUserSync.ts`；回归测试为 `plus-ui/src/utils/__tests__/dept-sync.test.ts`、`user-sync.test.ts`。

## 2. 配置

### 2.1 选择来源

`ruoyi-admin/src/main/resources/application.yml`：

```yaml
# 组织信息来源：hrm 泛微 OA 人力资源；none 不启用组织同步
org-sync:
  source: hrm
```

| 取值 | 效果 |
| --- | --- |
| `hrm` | 加载 `ruoyi-common-hrm` 的客户端与 `/hrm/*` 联调接口，以及 `HrmOrgSyncSource`；同步按钮可用 |
| `none` | 不加载任何 HRM Bean，不读取也不校验 `hrm.*` 配置；行为见第 3 节 |
| 未配置 | 等同 `hrm`。`HrmAutoConfiguration`、`HrmQueryController`、`HrmOrgSyncSource` 的条件均为 `@ConditionalOnProperty(prefix = "org-sync", name = "source", havingValue = "hrm", matchIfMissing = true)`，与 `OrgSyncProperties.source` 默认值 `hrm` 一致 |
| 其他值 | 启动失败，提示「org-sync.source 只能为 hrm 或 none」，不会静默当作 `none` |

取值只接受小写。修改后重启后端。

### 2.2 HRM 连接

`application-dev.yml`、`application-prod.yml` 中的 `hrm.*`：

| 配置 | 环境变量 | 说明 |
| --- | --- | --- |
| `hrm.endpoint` | `HRM_ENDPOINT` | SOAP 服务地址，不含 `?wsdl`。dev 默认 `http://139.224.241.191:8080/services/HrmService`，prod 默认内网 `http://10.20.9.143:8080/services/HrmService` |
| `hrm.client-ip` | `HRM_CLIENT_IP` | 传给 OA 的白名单客户端 IPv4，默认空 |
| `hrm.connect-timeout-seconds` | — | 连接超时，10 秒 |
| `hrm.read-timeout-seconds` | — | 请求超时，30 秒 |
| `hrm.log-response-body` | — | 脱敏响应正文日志开关，默认 `false`，仅诊断时临时打开 |

- `client-ip` 为空时应用照常启动，也能正常维护本地部门；只有实际调用 HRM（同步、填写绑定、调用 `/hrm/*`）时才报「hrm.client-ip 必须是 OA 白名单中的客户端 IPv4 地址」。
- `client-ip` 必须是**已由接口方确认加入 OA 白名单**的部署机器地址，开发电脑与服务器取值不同。通过环境变量注入，不要写入配置文件或提交仓库。
- 应用启动时不访问 OA。

## 3. `none` 模式

- 部门管理「同步子部门」、用户管理「同步员工」按钮不隐藏；点击并确认后，后端第一步即返回「未启用组织信息来源，无法同步」，由前端请求封装弹出提示，不读取部门、不加锁。
- 部门表单的「类型」「业务 ID」选填。填写时仍校验两项须同时填写、类型取值、ID 格式和业务身份唯一，但不调用外部来源确认；不填时按普通本地部门保存。已绑定部门绑定未变时保留既有来源快照字段，新绑定或改绑时清空快照。
- `/hrm/*` 联调接口不注册，接口不存在。
- 本地部门、用户的正常增删改不受影响。

## 4. `hrm` 模式下的部门绑定

- 类型（`subcompany` 分部 / `department` 部门）和业务 ID **选填**。都不填即普通本地部门，不调用来源，HRM 不可达也能保存。
- 填任一项则两项都必须填写；前后空白去除，空白值规范为 null。随后校验格式、身份唯一，并调用来源确认分部或部门存在、本地上级与来源上级关系一致；来源调用失败则不保存。
- 已绑定部门修改时两项都留空，表示**保留原绑定**，不能通过清空来解绑。改绑仅在部门无同步记录、无直接用户且无后代时允许，否则提示「已有用户、子部门或同步记录，禁止重绑」。
- 未完整绑定（缺类型、业务 ID 或所属分部）的部门不能发起部门同步，提示「部门未完整配置组织来源绑定」；员工同步要求选中的是已绑定业务 ID 的普通部门（`department`）。

## 5. 同步规则摘要

规则以 dev-bench 仓库最新代码为准移植（其规格文档 `docs/superpowers/specs/2026-10-13-部门类型与HRM子部门同步设计.md`、`2026-10-13-用户HRM员工同步设计.md` 可作背景参考）。注意 dev-bench 提交 `bdfe352`「不拉取删除部门用户」改变了停用部门的处理，其部门规格文档未同步更新，本项目以 `bdfe352` 之后的代码行为为准。

### 5.1 部门子树同步

`POST /system/dept/{deptId}/sync-children`，权限 `system:dept:sync`。

- 以点击的部门为锚点，拉取其所属分部的完整部门快照，新增或更新锚点下的后代部门，写入名称、排序、来源原始字段和同步时间。
- 来源中**停用的部门连同整棵子树跳过**，不新增、不更新；点击的普通部门本身在来源中已停用时，同步集合为空仍算成功。结果中的「参与同步」数量已排除这些节点。
- 本地部门下有用户时，不改动其本地状态，只在结果中给出状态保护提示。
- 来源中不存在的本地部门不会被自动删除或停用。
- 同一分部同一时间只允许一次同步（「该分部正在同步，请稍后重试」）。写入在一个事务中完成，任一步失败整体回滚；锚点上级在来源中已变化时要求先同步上级。

### 5.2 部门员工同步

`POST /system/user/{deptId}/sync`，权限 `system:user:sync`。前置校验依次为：来源已启用、部门存在、有该部门数据权限、是普通部门、已绑定业务 ID、已配置参数 `sys.user.initPassword`。

- 按外部人员 ID 匹配本地账号（`sys_user.hrm_user_id`）；未匹配时按登录名找同名本地账号并绑定，登录名比较不区分大小写，同名账号已绑定其他外部人员则跳过。
- 外部状态为空的记录跳过，不作为离职处理。
- 外部状态非在职、且本地上次同步时为在职的账号会被停用；重新在职的账号不会自动启用，需管理员手动处理。新增账号为正常状态，使用初始密码。
- 超级管理员账号从不修改；超出当前数据权限的账号跳过。
- 员工按其实际所属的外部部门 ID 落到对应本地部门（可调岗到其他已绑定部门）；匹配范围是未删除、有数据权限的普通部门，已停用但未删除的部门仍可接收员工。
- 本次来源未返回的已绑定员工只给出提示，不会被停用或删除。
- 同一部门同一时间只允许一次同步；写入在事务中完成。

结果弹窗显示统计和提示清单。日志与返回结果不包含手机号、邮箱、证件号等人员信息或 OA 原始响应正文。

## 6. 新增一个组织信息来源

1. 在 `ruoyi-system` 实现 `org.dromara.system.service.OrgSyncSource`：
   - `source()`：返回来源标识，与 `org-sync.source` 取值一致；
   - `listSubcompanies()`：全部分部；
   - `listDepartments(subcompanyId)`：一个分部的完整扁平部门快照，需经 `OrgSnapshotValidator` 校验并父先子后排序；外部返回「无结果/无权限」时抛 `ServiceException`，不能返回空列表冒充成功；
   - `listEmployees(departmentId)`：部门员工，外部 null 结果按无人员处理；
   - `isActiveStatus(rawStatus)`：把本地已存的原始员工状态翻译为是否在职，null 返回 false。
2. 在实现类上加 `@ConditionalOnProperty(prefix = "org-sync", name = "source", havingValue = "<标识>")` 并注册为 Bean。同一时刻只能有一个 `OrgSyncSource` 实现生效。
3. 在 `OrgSyncProperties` 中加入标识：既要增加常量，也要修改 `@Pattern(regexp = "hrm|none", ...)` 的正则和提示文案——正则与常量是两份字面量，须手工保持一致。
4. 来源格式细节（字段名、状态取值、性别、时间格式、名称回退）全部在适配层转换；通用层只看 `disabled`、`active` 等中性字段，不写来源字面量。
5. 字段写入既有 `hrm_*` 列：`hrm_` 前缀是历史命名，含义为「外部组织来源的原始值」，例如来源原始状态写入 `sys_dept.hrm_canceled`、`sys_user.hrm_status`。不要为新来源新增列或表。
6. 如果新来源也需要联调接口，参照 `ruoyi-common-hrm` 另建模块，并让它的自动配置使用同样的条件加载。

## 7. HRM 联调

### 7.1 只读联调接口

仅 `org-sync.source` 为 `hrm`（或未配置）时注册：

| 接口 | 权限 |
| --- | --- |
| `GET /hrm/subcompanies` | `hrm:subcompany:query` |
| `GET /hrm/departments` | `hrm:department:query` |
| `GET /hrm/job-titles` | `hrm:jobtitle:query` |
| `GET /hrm/users` | `hrm:user:query` |

返回 OA 获取到的全部字段（人员接口含证件号、联系方式等），只供有权限的管理员排查使用。Postman 调用方法、参数说明、诊断日志（`requestId` 关联请求、响应和解析结果）、`hrm.log-response-body` 的使用和真实 OA 联调测试 `HrmLiveTest`，见模块 [README](../ruoyi-common/ruoyi-common-hrm/README.md)。要点：

- 登录后台取得 `access_token`，请求头带 `Authorization: Bearer <access_token>` 和登录时使用的 `clientid`；不要把令牌存入共享集合或提交仓库。
- `hrm.log-response-body` 默认关闭；诊断时临时设为 `true` 并重启，复现后按 `HRM 响应正文` 和 `requestId` 定位，结束后改回 `false`。

### 7.2 客户端访问路径与 IP 限制

安全拦截器 `ruoyi-common-security` 的 `SecurityConfig` 对所有需登录的接口（含 `/hrm/**` 和两个同步接口）校验 `sys_client` 的配置：

- 「允许访问路径」（`access_path`）非空时，请求路径必须匹配其中一条，否则返回「当前客户端未授权访问该接口路径」；
- 「IP白名单」（`ip_whitelist`）非空时，请求来源 IP 必须匹配，否则返回「当前客户端IP不在白名单内」；
- 两项为空表示不限制。规则写入登录令牌，修改后需重新登录才生效。

初始化数据中，管理后台客户端 `pc` 两项均为空，不拦截 `/hrm/**`；`app` 客户端限制为 `/app/**`，会拦截。若某个客户端配置了路径或 IP 限制又需要调用联调接口，在「系统管理 → 客户端管理」中编辑该客户端：在「允许访问路径」中追加 `/hrm/**`，在「IP白名单」中追加当前来源 IP（多条规则用换行、逗号或分号分隔），然后重新登录。代码中不默认放开。

注意：这里的「IP白名单」是本系统对调用方的限制，与 OA 侧对 `hrm.client-ip` 的白名单是两回事。

### 7.3 待接口方确认

- 白名单校验的是 `in0` 参数（即 `hrm.client-ip`），还是实际出口 IP；
- `nullResult=true` 是否表示没有权限；
- 人员接口只传 `departmentId` 时，是否包含子部门的人员；
- 人员 `status` 的完整枚举；`loginid` 是否与三生 SSO 账号（本项目以 `adAccount` 绑定）一致。

## 8. 权限

- `system:dept:sync`（「部门管理 → 同步子部门」）与 `system:user:sync`（「用户管理 → 同步员工」）为按钮菜单，初始化时不授予任何种子角色，仅超级管理员拥有；需要时在「系统管理 → 角色管理」中为角色勾选。
- `hrm:*:query` 没有对应菜单，超级管理员通过通配权限可用；普通角色如需使用，需另行处理权限数据。

## 9. 限制

- 当前在公司外网，以下内容**均未联调**：真实 SOAP 调用、OA IP 白名单、HRM 字段的实际取值、浏览器端到端同步。验证仅限离线单元测试（本机临时 HTTP 服务模拟 OA、mock 来源）。
- 事务回滚和唯一索引未在真实 MySQL 上验证（本机无测试库）。
- 仅更新了 MySQL 初始化脚本 `script/sql/ry_vue.sql`；Oracle、PostgreSQL、SQL Server 脚本未更新。`script/sql` 只用于新库初始化，已有数据库需自行按 `ry_vue.sql` 中 `sys_dept`、`sys_user` 的新增列、索引及两条按钮菜单补齐。
- `SysDeptMapper.xml`、`SysUserMapper.xml` 中同步用的锁定查询使用 MySQL 专用的 `FORCE INDEX`，换用其他数据库时需调整。
