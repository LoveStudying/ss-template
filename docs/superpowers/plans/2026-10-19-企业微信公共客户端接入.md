# 企业微信公共客户端接入实施计划

**目标：** 在 common 下新增 `ruoyi-common-wecom`，用 WxJava 4.8.0 对接用户指定的七个只读或授权入口接口，并执行可获得参数范围内的真实联调。

**设计：** 沿用 HRM 模块的自动装配方式，默认关闭，以环境变量提供企业 ID、应用密钥和 AgentId。使用核心 SDK，不引入其 Spring Boot 2 starter。不新增 HTTP 控制器、数据库、前端、组织同步来源或登录策略；对外提供可注入的只读 `WecomClient`。保留 SDK 单 JVM 令牌缓存，当前阶段不扩展分布式缓存。

**技术约束：** Java 21、Spring Boot 4.1.1、Maven Wrapper、JUnit Jupiter；凭据及真实响应不入库，SDK 原始请求日志关闭。新增 public 方法使用中文 JavaDoc。

**接口：** `getAccessToken()`、`getAuthUserInfo(String code)`、`getUser(String userId)`、`listUsers(long departmentId, boolean fetchChild)`、`listDepartmentIds(Long departmentId)`、`getDepartment(long departmentId)`、`buildAuthorizationUrl(String redirectUri, String state)`。查询返回 SDK 类型，失败保留错误码且不传播原始响应。

## 验收关注

- 身份查询必须为 `/cgi-bin/auth/getuserinfo`，不能误用 SDK 的旧 `getUserInfo` 路径。
- 部门 ID 列表从 `department_id` 解析；单个部门从 `department` 对象解析。
- 企业微信业务错误属于联调结果，不能描述成所有接口调用成功；缺失参数、IP 白名单及权限限制须明确报告。
- OAuth code 不重放；授权链接验证不能替代用户在企业微信浏览器中的真实授权。
- SDK 原始异常、日志、Surefire 报告均不得包含真实密钥、令牌或成员资料。

- 最终模块测试：19 项通过，1 项真实探测默认跳过；真实探测单独显式运行，五项远端接口成功。模板结构检查及差异检查通过，密钥文件审计未发现测试密钥。
