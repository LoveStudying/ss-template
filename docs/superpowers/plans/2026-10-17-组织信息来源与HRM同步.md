# 组织信息来源与 HRM 同步实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 dev-bench 已在内网跑通的 HRM 部门/员工同步迁入 ss-template，HRM 协议客户端做成 `ruoyi-common-hrm`，同步逻辑只依赖可替换的 `OrgSyncSource` 接口，由 `org-sync.source`（`hrm` 默认 / `none`）选择。

**Architecture:** `ruoyi-common-hrm` 只负责 SOAP 协议与 4 个只读联调接口，按 `org-sync.source=hrm` 条件加载。`ruoyi-system` 定义 `OrgSyncSource` 与中性模型，`HrmOrgSyncSource` 适配实现吸收全部 HRM 字段格式；dev-bench 的 planner/writer/lock 移植为与来源无关的通用规则。前端按 dev-bench 组合式函数增量修改部门页与用户页。

**Tech Stack:** JDK 21、Spring Boot 4.1.1、MyBatis-Plus、Redisson、Sa-Token、JUnit 5 + Mockito；Vue 3 + TS、Element Plus、Vitest。

**Spec:** `docs/superpowers/specs/2026-10-17-组织信息来源与HRM同步设计.md`（必读，本计划不重复其规则）

**参考实现：** `D:\program\dev-bench`。相关提交按顺序：`1670530`、`342de2a`、`897830b`、`5215340`、`8ba12a1`、`6cbf81d`、`9da5e23`（客户端），`e4d05f1`（部门同步），`c52f09e`、`886cd8f`（员工同步），`bdfe352`（停用部门跳过）。**移植一律取 dev-bench 当前 HEAD 的文件内容**，提交号只用于定位改动范围。本项目 `SysDeptServiceImpl`、`SysUserServiceImpl`、`SysDeptMapper`、`SysUserMapper`、`SysDeptController`、`SysUserController`、`SysUser` 与 dev-bench `e4d05f1~1` 仅换行符不同，可按 `git -C D:/program/dev-bench diff e4d05f1~1 HEAD -- <path>` 的 diff 套用。
